# AI 自检：证据与定位

结果来源为成功读取的 Figma REST 文件快照。输入缺失、响应异常、空范围、重复 ID 或找不到指定节点会停止检测，不生成替代结果，也不会扩大检测范围。

- 报告保存文件版本、读取时间、原始响应 SHA-256（浏览器支持时）和完整规则配置。再次检测会重新读取文件。
- 所有规则记录包含真实节点 ID、路径、依据、实测值、阈值及受影响节点列表。规则阈值是项目配置，不等于完整合规或汽车安全认证。
- 实测偏差、待人工确认、未能检测分开计数。无数据不算通过；不生成总合规评分。
- 隐藏节点及其子节点不参与可见文本、对比度、触控候选检测。
- 对比度仅在可验证的单一不透明色对上计算；混合文本、图片、透明、效果、遮挡或未知背景不估算比值。同色文字与背景不会被跳过。
- 组件不自动视为按钮。候选触控边界、裁剪溢出、主组件嵌套等仅作为待确认项，不能据静态文件证明业务或性能故障。
- 截图请求固定文件版本并使用 `use_absolute_bounds=true`。框选使用节点与画板的真实绝对坐标差、百分比缩放和祖先链，避免同名节点、跨页面重叠坐标或旧版本截图错配。
- 图片失败时只显示错误提示，不展示示意设计。隐藏、范围外或缺少边界的节点只提供原稿定位，不编造坐标。
- AI 只复核首张同版本截图，并明确显示覆盖范围。AI 建议始终标为未验证，不绘制猜测节点框，不合并为规则错误或通过结论。
- AI 解析失败、缺少证据、异常置信度、超时或服务未配置，均不生成“空问题=通过”的替代结果。新导入和断开连接会阻止旧异步结果覆盖当前文件。

## 连接

Figma 读取需要可访问该文件的 Token（站点设置中配置本地 Token，或服务端 `FIGMA_API_TOKEN`）。不要把凭据提交到仓库或写进链接。

AI 截图复核需要服务端 `ARK_API_KEY` / `JIMENG_API_KEY`，以及可用的 `VISION_ENDPOINT_ID`。缺少 AI 配置不影响节点规则检测。截图仅经站点自身代理下载，发送给已配置的视觉模型；不会为自检使用第三方图片代理。

## 验证

运行 `node --test server/audit-integrity.test.mjs server/sites-api.test.mjs` 和 `npm run build`。

测试数据明确隔离在测试文件内，是合成边界条件，不是任何用户文件的检测报告。浏览器端到端验证还需要可访问的预览环境及真实文件授权；测试通过不等于已经验证某份真实文件的全部视觉问题。
